# RGB-D 与标定文件格式

## RGB-D ZIP

根目录直接放这些文件；不需要套一层目录：

```text
color.png        # RGB uint8，H×W×3
depth.npy        # H×W 数值数组，禁止 pickle
metadata.json
points.npy       # 可选：H×W×3 float，SDK 生成的相机光学 XYZ，单位 m
```

`metadata.json` 示例：

```json
{
  "schema": "depthbridge-frame-v1",
  "intrinsics": {
    "width": 640, "height": 480,
    "fx": 610.0, "fy": 610.0, "cx": 319.5, "cy": 239.5,
    "model": "none", "distortion": []
  },
  "depth_scale_m": 0.001,
  "aligned_to": "color",
  "timestamp": 0.0,
  "source": "import",
  "serial": "camera-serial",
  "description": "已对齐的 RGB-D 记录"
}
```

上面的 `0.001` 适用于 `depth.npy` 每单位为 1 mm 的数据；浮点米制深度应设为 `1.0`。它必须来自实际数据约定，不要假定所有 16 位深度都是 mm。`points.npy` 始终是米，不乘 `depth_scale_m`。

`aligned_to: color` 表示已经完成深度到彩色的几何对齐。内参必须属于对应彩色像素坐标系，图像、深度、XYZ 尺寸一致。工具会检查声明和形状，但无法从一个 ZIP 自动证明它实际正确对齐。

无 `points.npy` 时支持 `none`、`brown_conrady`、`opencv`、`plumb_bob`、`rational_polynomial` 模型。非零 Brown 畸变需 4/5/8/12/14 个 OpenCV 顺序系数。RealSense 的其他模型应由 SDK 生成 XYZ 后保存。

导入限制：压缩包和解压后的总数据不超过 100 MB，图像不超过 800 万像素。工具按固定文件名读取，不将任意 ZIP 路径解压到磁盘。

## 坐标矩阵

```text
T_base_from_camera =
[[r11,r12,r13,tx],
 [r21,r22,r23,ty],
 [r31,r32,r33,tz],
 [0,  0,  0,  1]]

p_base = R @ p_camera + t
```

平移为米，旋转为正交矩阵且行列式 +1。输入与输出都使用列向量语义。机器人 SDK 的欧拉角顺序各不相同，工具不默认猜测某厂商的角度约定；应先转换成明确的 4×4 矩阵。

## 标定 JSON / 会话 JSON

标定格式标识 `depthbridge-calibration-v1`，含 `units=meters`、`direction`、`matrix`、`mode`、`source_id`、`synthetic` 和质量摘要。

会话格式标识 `depthbridge-session-v1`，含选点原始相机坐标、采集时间、帧 ID、采集时变换快照、实测基座点、点用途与手眼观测。导入时校验数据源，避免跨设备或将合成变换应用到真机。会话不内嵌图像，图像需要另存 RGB-D ZIP。

0.2 帧包与新选点另含 `capture_key`，由进程随机命名空间和帧计数组成。浏览器选点携带该标识，服务端验证它与缓存帧一致；恢复旧会话仍可查看历史坐标，但不会将旧点叠加到另一帧上。旧 API 客户端可省略该字段，仍受帧缓存过期检查约束。

当前实时设备 `source_id` 为 `realsense:<serial>`，导入帧为文件内容哈希。合成示例单独标记 `synthetic=true`。

## 误差

- 逐点误差：`norm(predicted_base - measured_base) × 1000`，单位 mm。
- RMS：`sqrt(mean(error_mm**2))`。
- 三维点拟合摘要是训练残差；验证点独立统计，不参与矩阵拟合。
- 手眼摘要是观测之间的一致性，不是机械臂实际抓取精度。
